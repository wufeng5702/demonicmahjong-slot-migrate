# AGENT.md

A guide for AI agents (and human contributors) working on this repository.

## Project

Wails v3 desktop app that migrates Android save data for 《我在地府打麻将》
to the Steam installation on Windows.

- **Backend**: Go 1.25, Wails v3 (`github.com/wailsapp/wails/v3 v3.0.0-beta.11`)
- **Frontend**: Vue 3 + TypeScript + Vite, dependency-managed with `pnpm`
- **Package manager rule**: frontend uses `pnpm` (never `npm`/`yarn`)
- **Save DB**: SQLite (`modernc.org/sqlite`, pure-Go driver — no CGO)

## Wails v3 architecture notes

### Service registration (critical pattern)

Services need the `*application.App` for Dialog/Logger/Events. **Always create
the app first, then inject it via a constructor**, then register:

```go
app := application.New(application.Options{...})
app.RegisterService(application.NewService(android.NewService(app)))
app.RegisterService(application.NewService(migrate.NewService(app)))
app.RegisterService(application.NewService(steam.NewService(app)))
```

Do **not** register zero-value structs like `&android.Service{}` — the `app`
field will be `nil` and every call fails with "app is not initialized".

### Binding method signature (mandatory)

Every exported service method exposed to the frontend MUST use the request/
response envelope, even when the payload is empty:

```go
func (s *Service) MethodName(req *MethodNameRequest) (*MethodNameResponse, error)
```

This keeps `wails3 generate bindings` output uniform and avoids the v3
generator silently dropping empty structs. Empty request structs are fine:

```go
type AutoFetchAndroidDBRequest struct{}
```

### Regenerating bindings

After changing any Go service signature or model field:

```powershell
wails3 generate bindings -ts
```

The `-ts` flag emits TypeScript bindings (`.ts`), which is what the frontend
imports. Without `-ts` the generator emits `.js`, breaking `vue-tsc --noEmit`.

Bindings are committed to the repo (`frontend/bindings/`) so CI can `pnpm build`
without running the generator.

### Embedded adb

`internal/android/embedded/` contains `adb.exe`, `AdbWinApi.dll`,
`AdbWinUsbApi.dll` checked into the repo. They are extracted to
`%LOCALAPPDATA%\wodima-migrate\adb-{ADBVersion}\` at runtime. Bump
`ADBVersion` in `adb.go` to force a re-extraction after upgrading the binaries.

### Android save paths

`GameDBPaths` in `internal/android/adb.go` lists candidate on-device paths,
tried in order:

1. Standard install: `/sdcard/Android/data/com.itaotuo.wodima/files/game.db`
2. TapTap sandbox: `/sdcard/Android/data/com.taptap/files/tap_sandbox_sd/0/Android/data/com.itaotuo.wodima/files/game.db`

`PullGameDB` returns the source path that succeeded, so the frontend can
label rows as "独立安装包" or "TapTap 启动".

## Development

### Prerequisites

- Go 1.25+
- Node.js 22+
- pnpm 11+
- Wails v3 CLI: `go install github.com/wailsapp/wails/v3/cmd/wails3@latest`

### Run in dev mode

```powershell
wails3 dev -config ./build/config.yml -port 9245
```

or via Taskfile:

```powershell
task dev
```

### Build

```powershell
wails3 build        # debug build
task build          # via Taskfile (preferred)
```

### Frontend only

```powershell
cd frontend
pnpm install
pnpm build      # vue-tsc --noEmit && vite build
pnpm lint
pnpm format
```

### Full local verification before commit

```powershell
wails3 generate bindings -ts      # 1. regenerate TS bindings from Go signatures
cd frontend; pnpm build; cd ..     # 2. build frontend/dist (MUST happen before go build)
go build .                         # 3. embed the freshly built frontend/dist
go test ./...
golangci-lint run
```

Or simply use the Taskfile, which enforces the correct order:

```powershell
wails3 build
```

## Conventions

### Git commits

- Use [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/):
  `feat:`, `fix:`, `refactor:`, `docs:`, `chore:`, `build:`, `ci:`.
- Commit messages in English.
- Only commit when the user asks. If on the default branch, branch first.

### Code style

- **Go**: `gofmt` + `gci` (import grouping) via `.golangci.yaml`. Linter config
  enforces `interface{}` → `any` rewrite, line length ≤ 380, etc.
- **Line endings**: `.gitattributes` forces LF for Go/TS/Vue/YAML. This is
  required because `gci` is sensitive to CRLF and CI runs on Windows runners
  where `core.autocrlf=true` would otherwise corrupt files.
- **Frontend**: Prettier + ESLint + vue-tsc. Husky `pre-commit` runs
  `lint-staged` on staged frontend files.
- Comments in English, only where the logic is non-obvious.

### PowerShell

The user's shell is PowerShell on Windows 10. Generated commands must be
PowerShell-compatible (use `;` not `&&` where needed, backtick line
continuation, etc.).

### Firewall note for Wi-Fi feature

The Wi-Fi upload server listens on `0.0.0.0:<random-port>`. Windows Firewall
on "Public" networks blocks inbound by default. The UI surfaces two fixes:

1. `Set-NetConnectionProfile -NetworkCategory Private` (recommended)
2. `netsh advfirewall firewall add rule name="..." dir=in action=allow protocol=TCP localport=<port> profile=any`

If a user reports `net::ERR_CONNECTION_ABORTED` from the phone, the network
profile is almost always the cause.

## CI

- `.github/workflows/ci.yml` — builds the app on `windows-latest`.
- `.github/workflows/lint.yml` — `golangci-lint` (needs `pnpm build` first so
  `//go:embed all:frontend/dist` resolves) + `pnpm lint`.
  `skip-cache: true` is set because the action's cache can serve stale results
  after binding refactors.
- `.github/workflows/release.yml` — triggered by `v*` tags. Builds with
  `wails3 build`, uploads `bin/*.exe` and `bin/*.zip` to a GitHub Release.

## Common pitfalls

1. **`app is not initialized`** — service registered as zero-value struct
   instead of via `NewService(app)`. See "Service registration" above.
2. **`pattern all:frontend/dist: no matching files found`** — `frontend/dist`
   is gitignored. CI/lint must run `pnpm build` before `go build`/`golangci-lint`.
3. **`gci: File is not properly formatted`** only on CI — line endings.
   Ensure `.gitattributes` is committed and covers the file type.
4. **Bindings out of sync** — after editing Go service signatures, run
   `wails3 generate bindings -ts` and commit the regenerated files, otherwise
   `vue-tsc` will fail or calls will silently mismatch.
5. **`-webview2` flag needs an argument** — use `wails3 build -webview2 embed`
   (or `download`/`browser`).
6. **Stale frontend embedded in binary** — `go build .` embeds whatever is in
   `frontend/dist` at that moment. If you run `go build` and `pnpm build` in
   parallel (or in the wrong order), the binary will contain the OLD frontend
   and the UI will silently misbehave (e.g. status messages never update).
   Always run `pnpm build` BEFORE `go build`, or use `task build`.
